Аннотация
Рассмотрены классические методы компьютерного зрения для трёх детекторов нештатных
ситуаций в помещении. Сопоставлены существующие научные подходы, доступные открытые
реализации и предварительная применимость к LicheeRV Nano (SG2002) с камерой GC4653. Оценки
вычислительной сложности носят качественный характер. Проверка алгоритмов на плате и
подтверждение метрологических порогов не выполнялись.

2.2. Предварительный выбор
Рекомендован базовый конвейер: Y-кадр → обновление фона → бинарная маска движения →
морфологическая фильтрация → связные компоненты/контуры → фильтрация малых областей →
сопровождение → пересечение ROI/границы → событие. В качестве алгоритмов сравнить простой
адаптивный фон и MOG2/IVE GMM2; ViBe рассмотреть как альтернативу при недостаточной
скорости или точности.
Важно: площадь силуэта в пикселях не равна площади 0,5 м². Для физической оценки размеров
требуется геометрическая модель сцены, масштаб на расстоянии объекта или контрольные
тестовые объекты. Классическое вычитание фона не различает «человек», «животное», «штора»
без дополнительной классификации.

2.3. Публикации и готовый код
OpenCV Background Subtraction — официальная документация и базовые примеры [6, 7]. ViBe
(Barnich, Van Droogenbroeck, IEEE TIP, 2011) — публикация и авторский исходный код C/C++ [8].
BGSLibrary — открытая библиотека большого числа методов на C++/OpenCV, удобна для сравнения
на ПК [9]. CDnet 2014 — набор размеченных сцен для оценки масок движения [17].

3.2. Научная база
Töreyin, Dedeoğlu, Çetin (EUSIPCO 2005) предложили распознавать дым по ослаблению границ и
пространственной wavelet-энергии на неподвижной камере [10]. Другая работа развивает подход
дополнительными признаками контура и цветности [11]. Yuan (Pattern Recognition Letters, 2008)
рассматривает накопление направления движения для подавления ложных тревог [12].
Публикации подтверждают практическую обоснованность многопризнакового подхода, но не
гарантируют обнаружение при наших порогах.

3.3. Предварительный выбор
Для SG2002 наиболее рационален двухступенчатый алгоритм: (1) малозатратная генерация
подозрительных областей по изменению относительно эталона; (2) анализ только этих ROI по
потере локального контраста/резкости, плавной эволюции и движению за несколько секунд. При
необходимости использовать цветность UV, но не полагаться только на Y-канал. Нельзя считать
одно снижение контраста достаточным признаком дыма.
Требование «контраст не менее 20%» требует формулы, эталона и стандартизованной процедуры
измерения. Дым является объёмной полупрозрачной средой: его физическая площадь не всегда
может быть надёжно восстановлена по одному изображению. Дополнительно необходимо
определить минимальную продолжительность события, тип дыма, движение воздуха и режим
освещения.
Обнаружение дыма только камерой не должно рассматриваться как замена пожарной
сигнализации и специализированных извещателей.

3.4. Реализации и данные
Найдена практическая реализация измерения дымовой непрозрачности по относительному
контрасту между зонами IP-камеры [13]; это проект для заданной сцены, не готовый
промышленный детектор и не код под SG2002. Из публичных наборов полезны VisiFire/FIRESENSE,
MIVIA и MmodalFire. Последний особенно релевантен: видеозаписи сделаны в помещениях с
синхронными физическими измерениями, включая дым, пар и водяной туман [18–20]. Большинство
общих датасетов не размечены непосредственно по порогу «20% контраста».

4.2. Предварительный выбор
Следует разделять два разных процесса: сначала проверить, не сдвинулась ли камера
относительно статичного фона; затем независимо измерить сдвиг контролируемого объекта.
Иначе смещение камеры будет ошибочно интерпретировано как смещение объекта. Для
протяжённых объектов с чёткой кромкой предпочтителен анализ контуров и положения линии;
для фактурных фрагментов — template matching или phase correlation. ECC может служить для
стабилизации фонового эталона [14–16].
Для площади наблюдения шириной 10 м один пиксель на исходном кадре 2560 px соответствует
примерно 3,9 мм на плоскости, перпендикулярной оси камеры. Смещение 5 см ≈12,8 пикселя. На
уменьшенном изображении 640 px тот же сдвиг ≈3,2 пикселя. Это только иллюстрация идеального
масштаба: без знания расстояния, фокусного расстояния и перспективы цифры не служат
доказательством обнаружимости. Приоритет — ROI исходного высокого разрешения.

4.3. Публикации и код

7. Будущая экспериментальная проверка — только план
Для проникновения: CDnet 2014 и собственные записи с GC4653 в реальном помещении; метрики
precision/recall, ложные тревоги в час, задержка и устойчивость к освещению. Для дыма:
MmodalFire, VisiFire, MIVIA, а затем собственные контролируемые записи с дымом, паром и
изменением освещения; метрики задержки и ложных тревог, связь с заданным определением
контраста. Для смещения: собственная геометрически размеченная сцена с контролируемым
перемещением объекта на 0/3/5/7/10 см; ошибки в сантиметрах, воспроизводимость, ложные
срабатывания при сдвиге камеры. Все испытания на устройстве должны измерять CPU/RAM/FPS и
время обнаружения, в том числе при независимом включении модулей.

10. Замечания по источникам
Основные статьи описывают алгоритмы в иных сценах и на ином оборудовании; перенос их
опубликованных метрик на LicheeRV Nano недопустим. Сторонние GitHub-проекты использованы
